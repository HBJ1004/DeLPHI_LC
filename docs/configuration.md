# DeLPHI settings and what can be changed

All settings of the K3 scorer live in three frozen dataclasses in
[`lc_pipeline/k3/config.py`](../lc_pipeline/k3/config.py). The values below are
the ones used for the manuscript (the configuration table in Appendix A of the paper). Some settings are
**locked**: the code raises `K3ConfigError` if they are changed. The locks protect
the fixed protocol of the paper and the compatibility of the released weights.
They do not mean that other values cannot work.

The published weights only work with the input and network settings they were
trained with. Changing any setting marked "retrain" requires training new
networks (see [training-your-data.md](training-your-data.md)).

## Input representation (`K3TokenizerConfig`)

| Setting | Value | Locked | Notes |
|---|---|---|---|
| `phase_bins` | 64 | yes | Phase bins per folded lightcurve. Retrain. |
| `fourier_harmonics` | 8 | yes | Harmonics 1 to 8 of the folded lightcurve. Retrain. |
| `minimum_epoch_observations` | 2 | yes | Observations needed for an epoch to be used. |

## Network (`K3ScoreModelConfig`)

| Setting | Value | Locked | Notes |
|---|---|---|---|
| `hidden_dim` | 128 | no | Transformer width. Must be divisible by `attention_heads`. Retrain. |
| `convolution_blocks` | 3 | no | Convolutional blocks over the phase bins. Retrain. |
| `set_encoder_layers` | 2 | no | Transformer layers across epochs. Retrain. |
| `attention_heads` | 4 | no | Retrain. |
| `dropout` | 0.1 | no | Retrain. |
| `phase_feature_count`, `epoch_feature_count` | 6, 22 | no | Fixed by the tokenizer. Change only together with it. |

## Candidate selection (`K3ScoreModelConfig`, used after training)

| Setting | Value | Locked | Notes |
|---|---|---|---|
| `nside` | 32 | yes | HEALPix resolution of the trial axes, 6,144 axes about 1.8 deg apart. |
| `candidate_count` | 3 | yes | Number of candidates K. Section 6.4.1 of the paper reads 1 to 6 peaks from the same maps. |
| `nms_separation_deg` | 15.0 | no | Minimum separation between candidates. Used by the Python scoring interface `lc_pipeline.k3.api`; the prediction command for the published networks, `delphi-k3-predict`, always uses 15°. Changing it needs no retraining. |
| `refinement_steps` | 8 | yes | Steps of the final adjustment. |
| `refinement_max_displacement_deg` | 5.0 | yes | Cap on the final adjustment. The adjustment slightly increased the mean error in the paper (Section 3.4). |
| `refinement_learning_rate` | 0.08 | no | Step size of the final adjustment. |
| `score_chunk_size` | 512 | no | Axes scored per batch during training and evaluation. Affects memory and speed only. The prediction command for the published networks scores 1,024 axes per batch, as in the archived predictions. |

## Training (`K3TrainingConfig`)

| Setting | Value | Locked | Notes |
|---|---|---|---|
| `seed` | 17, 42, 137, 777, 2027 | yes | Only these five seeds are accepted. |
| `batch_size` | 16 | no | Asteroids per update. |
| `learning_rate` | 3e-4 | no | AdamW. |
| `weight_decay` | 1e-4 | no | AdamW. |
| `synthetic_max_epochs`, `synthetic_patience` | 100, 15 | no | Passes over the simulated data and early-stopping patience. The custom training command (`repro.train_k3_custom`) also uses these limits. |
| `real_max_epochs`, `real_patience` | 30, 8 | no | The same for the real DAMIT data. |
| `encoder_finetune_lr_multiplier` | 0.25 | no | Learning rate of the photometry encoder, relative to `learning_rate`, during the real-data stage. |
| `synthetic_to_real_ratio` | (3, 1) | yes | Simulated to real asteroids during the real-data stage. |
| `uniform_negatives` | 48 | no | Directions drawn over the whole sphere per asteroid. |
| `hard_negatives` | 16 | no | Directions drawn near the first published solution. |
| `hard_negative_min_deg`, `hard_negative_max_deg` | 5, 45 | no | Range for the nearby directions. The exclusion zone below raises the effective minimum to 10 deg. |
| `negative_exclusion_deg` | 10 | no | No drawn direction lies closer than this to a published axis. |
| `rank_loss_weight` | 0.25 | no | Weight of the second loss term (Section 4.2 of the paper). |
| `gradient_clip_norm` | 1.0 | no | Limit on the size of each update. |
| `mixed_precision` | true | no | Half-precision arithmetic on CUDA. |
| `num_workers` | 0 | yes | Data-loader workers. Required for deterministic runs. |

## Simulated training data

The simulated asteroids are generated by
[`lc_pipeline/k3/synthetic.py`](../lc_pipeline/k3/synthetic.py) with a locked
split of 20,000 training, 2,000 validation and 2,000 test objects.

## How to change a setting

`repro/train_k3_custom.py` trains with the default `K3TrainingConfig` and
`K3ScoreModelConfig`. To experiment, construct the dataclasses with other values
in your own script, for example

```python
from lc_pipeline.k3.config import K3ScoreModelConfig, K3TrainingConfig

training = K3TrainingConfig(seed=17, learning_rate=1e-4, real_patience=12)
network = K3ScoreModelConfig(hidden_dim=256, dropout=0.2)
```

and pass them to `fit_k3` and `CandidateConditionedScorer` as in
`repro/train_k3_custom.py`. To change a locked setting, edit its check in
`config.py`. Results obtained with changed settings are not comparable with the
frozen manuscript benchmark, and they should be evaluated on asteroids that
were not used to choose the settings.
